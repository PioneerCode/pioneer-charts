The state timeline shows how something's status changed over time. Each row is one thing you're tracking, like a service or a device. Each row is split into periods, such as days or hours, and each period is colored by the worst state it reached. One hour of Error in an otherwise good day still shows up, and the longer it lasted, the darker the color.

Status History

This example shows four made-up services over 30 days. You can see an outage, a slowdown, a device that was off for a day and a half, and a backup that failed two days in a row. Hover over a day, or tab to it, to see its details.

The Data

data is a list of rows. Each row is a PcacData: its key is the row's name, and its data is the row's periods, oldest first. Each period has:

  • key: the period's name, shown in the tooltip and read by screen readers, like 'Fri, Nov 20' or '2 PM'.
  • value: how long the period is, in any unit (hours, minutes, milliseconds).
  • data: how much time the period spent in each state, in the same unit. Each entry's key matches a state's key.

Any time not covered by a state is unknown, for example because the device was off. A period that's partly unknown is striped, and a period that's entirely unknown is plain gray, so missing data never looks like OK. If you leave out value, the period's length is the total of its states, and none of it is unknown.

Each period takes the color of its worst state. "Worst" follows the order of states, which you list from least to most severe. The color is lighter when that state lasted a short time and full strength when it lasted the whole period. Every period in a row is the same width, even if their lengths differ.

Long Windows

When periods get narrow, the gap between them shrinks automatically: from 2px to 1px, and then to none if a period would otherwise be less than a pixel wide. This example fits 90 days into a narrow card.

Colors

By default, the first state is pale green, the last is a strong red, and any states in between are amber. Good periods stay in the background, and problems stand out. The colors differ in lightness as well as hue, so people with red-green color blindness can still tell them apart. The tooltip and screen reader text also name each state in words.

To change a color for one chart, set color on that state. Pick colors that differ in lightness, too. To restyle every chart inside an element, for example on a dark page, set the CSS custom properties below. This site's dark theme does exactly that.

Markup

API

states The states a period can be in, listed from least to most severe. Each has a key (matching the keys in the periods' data), an optional label for the tooltip and screen readers (defaults to the key), and an optional color (defaults to the theme's). gap Space between periods, in px. Default 2. It shrinks automatically when periods get narrow. rowLabels Show each row's key to its left. Default true. Labels use at most 40% of the width.

The rows split the height evenly, with 4px between them. The default height fits one row, so set a larger one for more rows. Keyboard users can move between periods with the arrow keys. Screen readers announce each period's row, name and states, for example "Database, Fri, Nov 6: Error 50%, OK 50%" (see Accessibility).
