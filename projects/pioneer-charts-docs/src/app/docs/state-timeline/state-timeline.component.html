State timeline component: one row for each thing watched, each a run of periods — days, hours — side by side, colored by the worst state it was in during that period. It answers "when did this go wrong, and how much?" at a glance: an hour of Error in a day otherwise OK still shows, deeper the more of the day it took.

Status History

Four services over the last 30 days, made up: an outage, a slow spell, a device switched off for a day and a half, and a backup that failed two days running. Hover or focus a day for what it was in.

The Data

data holds the rows, each a PcacData whose key is its name and whose data is its periods, oldest first. Each period has:

  • key: its name, which the tooltip and screen readers say — 'Fri, Nov 20', '2 PM'.
  • value: its length, in any unit: hours, minutes, milliseconds.
  • data: the time it spent in each state, in the same unit, keyed by the state's key.

Time the states don't cover is unknown — the device was off, the log hadn't begun. A period with some of it unknown is striped, and one with all of it unknown is plain gray, so a gap never reads as OK. Leave value out and the period's length is the time in its states: all of it known.

A period is drawn in the color of the worst state it was in, by the order of states (least severe first), from 75% of that color to all of it, the more of what's known of the period it took. Every period of a row is drawn the same width, whatever its length.

One Row, Its Own Tooltip

One service, as a status card holds it: rowLabels: false and 14px tall, with the totals written beneath it and a tooltip template giving each day's hours. The template's $implicit is the period itself, parent its row.

Long Windows

The 2px between periods drops to 1px once it would take more than a quarter of each period's room, and to none when even that would leave a period under a pixel wide. Here, 90 days in a narrow card.

Colors

The first state is drawn a pale green, the last a strong red, and any between amber: OK quiet, problems loud. They differ in lightness as well as hue, so a reader who can't tell red from green still tells them apart — and the tooltip and each period's name for screen readers say the state in words.

Give a state its own color in states to change it for one chart, keeping to colors that differ in lightness. To restyle every chart under an element — for a dark page, say — set the custom properties; this site's dark theme sets its own.

Markup

API

states The states a period can be in, least severe first: each a key (as the periods' data name it), a label (what the tooltip and screen readers call it; its key when unset) and a color (any CSS color; the theme's when unset). A period shows the last of them it was in. gap Space between periods, in px. Default 2; it narrows to 1px, then none, as the periods do. rowLabels Write each row's key to its left. Default true; the labels take up to 40% of the width.

The height is shared between the rows, 4px apart. Each period is one stop for the arrow keys, named for screen readers with its row, its name and what it was in — "Database, Fri, Nov 6: Error 50%, OK 50%" (see Accessibility).
